Setting Up OpenClaw on a Dedicated VM

Paul Snider Technology Executive & MBA

I set up OpenClaw on a dedicated VM and then used it to write this very blog post. Here is how the setup works, what I learned, and why a dedicated machine makes the whole experience smoother.

Why a Dedicated VM

I already had a Mini PC running Ubuntu that I use for remote AI prompting. Adding OpenClaw to this box was the obvious next step. A dedicated VM means:

  • Always available: The agent is ready whenever I SSH in
  • Isolated environment: No risk to my primary laptop or work machine
  • Persistent sessions: tmux keeps sessions alive between connections
  • Dedicated resources: No competition with other workloads

The Setup Process

Getting OpenClaw running was straightforward. The key steps:

Prerequisites

The VM was already running Ubuntu with SSH access, Git, and Node.js installed from my earlier "Prompting on the Go" setup. If you are starting fresh, you will need:

  • Ubuntu Server (22.04 or later)
  • Node.js 18+ and npm
  • Git configured with your GitHub credentials
  • SSH access to the machine

Installing OpenClaw

OpenClaw installs via npm. Once installed, you configure it with your API key and point it at a workspace directory:

# Install OpenClaw globally
npm install -g @anthropic-ai/claude-code

# Create a workspace directory
mkdir -p ~/.openclaw/workspace

# Clone your repos into the workspace
cd ~/.openclaw/workspace
git clone git@github.com:pauljsnider/paulsnidernet.git

Configuration

The main configuration involves setting your Anthropic API key and any project-specific settings. OpenClaw reads from a CLAUDE.md file in your project root for repo-level context, and you can add a global configuration for settings that apply across all projects.

Connecting from My Phone

Since the VM is already set up with SSH and port forwarding from my earlier project, connecting is just opening Termius on my phone and starting a session. From there:

# Attach to an existing tmux session
tmux attach -t openclaw

# Or start a new one
tmux new -s openclaw
cd ~/.openclaw/workspace/paulsnidernet
claude

Writing This Blog Post with OpenClaw

To prove the setup works, I used OpenClaw to write this blog post. The workflow looked like this:

  1. SSH into the VM from my phone
  2. Navigate to my personal site repo
  3. Ask OpenClaw to read the blog post spec and existing posts for patterns
  4. Give it the topic, slug, date, and category
  5. Review the generated HTML
  6. Have it update blog.html with the new card
  7. Commit, push, and open a PR

The entire process took a single prompt. OpenClaw read the spec, matched the existing patterns, created the HTML file, updated the blog index, and handled the git workflow.

What Works Well

A few things stood out:

  • Spec-driven workflow: Having a clear spec file (like the NEW-BLOG-POST.md in this repo) makes the agent precise. It follows the template exactly instead of guessing.
  • Pattern matching: Pointing OpenClaw at existing blog posts means the output is consistent with what is already there. No style drift.
  • Git integration: Branch creation, commits, and PRs happen without leaving the terminal. The agent uses gh CLI natively.
  • Mobile-friendly: Because everything runs on the VM, my phone is just a thin prompt interface. No heavy lifting required.

Lessons Learned

  • Start with a spec: The clearer your instructions, the better the output. A markdown spec with templates and examples beats verbal descriptions every time.
  • Use existing patterns: Telling the agent to look at existing files for patterns is more effective than describing the patterns yourself.
  • Dedicated machines reduce friction: No setup time, no context switching, no worrying about breaking your primary environment.
  • tmux is essential: Long-running agent sessions need persistence. Losing a session because your phone locked is frustrating without tmux.
The best part about this setup is that it disappears. You stop thinking about the infrastructure and just focus on what you want to build.

What is Next

Now that OpenClaw is running on the VM, I plan to use it for more of my personal site updates, project scaffolding, and automation tasks. The combination of a dedicated machine, SSH access, and an AI agent that understands your codebase is a powerful workflow for anyone who builds things on the side.
