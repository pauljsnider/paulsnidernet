Setting Up OpenClaw on a Dedicated VM

Paul Snider Technology Executive & MBA

I moved OpenClaw onto a dedicated Ubuntu VM so I could run coding sessions from anywhere and send updates into Slack. This setup gives me a stable always-on agent instead of a laptop-bound workflow.

Why a Dedicated VM

I wanted a setup that survives reboots, travel, and context switching. Running OpenClaw on a dedicated VM solved the operational issues I kept hitting on my daily machine:

  • Always available: I can SSH in from phone or laptop and continue immediately.
  • Isolated runtime: Experiments and tool installs stay off my primary workstation.
  • Persistent sessions: tmux keeps long-running work alive across disconnects.
  • Cleaner automation: Cron jobs, webhooks, and Slack notifications live in one place.

The Setup Process

Provisioning was straightforward and took about 20 minutes end to end.

Prerequisites

If you are starting from scratch, this is the minimum baseline:

  • Ubuntu Server (22.04 or later)
  • Node.js 18+ and npm
  • Git and GitHub authentication (SSH key or gh auth)
  • SSH access to the machine
  • A Slack Incoming Webhook URL (optional but recommended)

Installing OpenClaw

I keep all repos under one workspace directory so the agent environment stays predictable:

# Install OpenClaw globally
npm install -g @anthropic-ai/claude-code

# Create a workspace directory
mkdir -p ~/.openclaw/workspace

# Clone your repos into the workspace
cd ~/.openclaw/workspace
git clone git@github.com:pauljsnider/paulsnidernet.git

Configuration

I use a global env file for shared secrets and a project-level `AGENTS.md` / `CLAUDE.md` for repo-specific instructions. That keeps credentials separate from prompting rules and makes behavior consistent across sessions.

Connecting from My Phone

From my phone (Termius), I reconnect to the same session in seconds:

# Attach to an existing tmux session
tmux attach -t openclaw

# Or start a new one
tmux new -s openclaw
cd ~/.openclaw/workspace/paulsnidernet
claude

Slack Notifications

I added Slack notifications so I can see when a long task finishes without staring at the terminal. The VM posts status updates to a private channel using a webhook:

# ~/.openclaw/env
export SLACK_WEBHOOK_URL="https://hooks.slack.com/services/..."

# tiny helper script
curl -X POST -H 'Content-type: application/json' \
  --data '{"text":"OpenClaw run complete for paulsnidernet"}' \
  "$SLACK_WEBHOOK_URL"

This is intentionally simple: start with completion alerts, then expand to failures, PR links, or deploy summaries as needed.

Writing This Blog Post with OpenClaw

I used this exact VM setup to draft and publish this post. Workflow:

  1. SSH into the VM and attach tmux.
  2. Open the repo and run OpenClaw in that workspace.
  3. Point it at `spec/NEW-BLOG-POST.md` plus existing post examples.
  4. Generate post HTML and the `blog.html` card update.
  5. Review/edit, run quick validation, and push a PR.
  6. Send Slack completion message with the PR link.

The spec-first approach matters. When the instructions are concrete, the generated output is dramatically better and requires less cleanup.

What Works Well

After a week of using this setup, these are the clear wins:

  • Reliability: dedicated runtime means fewer broken sessions and less environment drift.
  • Speed: no local setup before each task; I just reconnect and continue.
  • Slack visibility: completion/failure notifications reduce polling and context switching.
  • Review quality: spec + existing file patterns produce cleaner first drafts.

Lessons Learned

  • Write the spec first: vague prompts produce vague code.
  • Keep Slack integration minimal: one webhook and a tiny script gets most of the value.
  • Treat tmux as required: mobile networks will drop; your session should not.
  • Separate secrets from prompts: env files for keys, repo docs for behavior.
A dedicated VM plus Slack alerts turns the agent from a demo into infrastructure.

What is Next

Next step is bidirectional Slack interaction: post run summaries automatically, then trigger predefined OpenClaw tasks from Slack commands for low-risk maintenance work. That should make this setup even more useful when I am away from my desk.
